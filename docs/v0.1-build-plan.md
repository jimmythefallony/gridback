# GridBack v0.1 — Build Plan (Coding Agent Brief)

**Product:** GridBack (working title)  
**Release target:** v0.1 only  
**Platform:** Native macOS, Swift, Apple Silicon (`arm64`), deployment target **macOS 26+**  
**Distribution:** Unsigned app archive / DMG via **GitHub Release**  
**Date:** 2 November 2026  

This brief is the implementation contract for v0.1. Do **not** implement folders, pinch, Sparkle, Homebrew, telemetry, import, or badges here.

---

## 1. Goal

Ship a **menu bar** app that opens a **full-screen-style app grid overlay** on the **primary display** from a **configurable keyboard shortcut**, with click-to-launch, type-to-search, Escape-to-close, drag-to-reorder, and **local persistence** of layout order.

## 2. In scope / out of scope

### In scope

- Menu bar extra: Open GridBack, Settings (at least shortcut), Quit
- Global configurable keyboard shortcut (toggle open/close)
- Overlay on configured **primary** display (not pointer location; not duplicated on secondary displays)
- Discover installed apps; show native icons + display names
- Horizontal paging + page indicators (simple classic-style grid)
- Single-click launch via macOS APIs; dismiss overlay after accepted launch request
- Type-to-search across discovered apps; Escape clears search then dismisses (see Escape rules)
- Drag-and-drop reorder on the main grid; page-local compaction; persist order locally
- Fresh layout on first run (deterministic display-name sort is an acceptable default)
- English UI strings; keep strings localizable later
- README with build/run instructions; GitHub Release packaging notes for an unsigned build

### Out of scope (do not build in this PR / milestone)

- Trackpad pinch / MultitouchSupport / OpenMultitouchSupport
- Folders, nested folders, legacy Launchpad DB import
- Start at Login (can stub UI later; not required for v0.1 acceptance)
- Sparkle, notarization, Developer ID signing, Homebrew
- Telemetry, crash reporting, badges, F4-specific hardware claims beyond “shortcut works if available”
- Intel / macOS &lt; 26 support

## 3. Architecture (implementation defaults — verify before locking in)

Mark these as **defaults to verify** against current Apple docs/SDK; replace if a verified API is better.

| Area | Default approach |
|------|------------------|
| UI | **SwiftUI** for grid/settings where practical; **AppKit** for windowing / activation |
| Overlay window | Borderless **`NSPanel`** (or equivalent) at a suitable level, full-screen *style* on one display — **not** entering a separate full-screen Space |
| Primary display | Resolve the display macOS marks as primary (do **not** assume `NSScreen.main` alone is enough) |
| App discovery | **`NSWorkspace`** / Launch Services–style enumeration of standard Application folders; refresh on install/remove events where documented APIs allow |
| Launch | `NSWorkspace.shared.openApplication` (or current documented equivalent) — never shell-exec the binary path |
| Icons / names | Workspace / bundle metadata; neutral fallback if missing |
| Shortcut | Carbon/`MASShortcut`-style or `KeyboardShortcuts` / AppKit global hotkey — pick one maintained approach and document it; fail clearly if registration fails |
| Persistence | Small local store (e.g. Application Support JSON or similar) for ordered layout + settings; atomic writes |
| Search | In-memory filter on display name (case-insensitive); no Spotlight dependency required for v0.1 |
| Process model | Single app process; menu bar agent-style (`LSUIElement` / accessory) so it does not appear as a normal Dock app by default — **verify** Info.plist flags |

Logical modules (names flexible):

```
GridBack/
  App/                 # @main, menu bar, lifecycle
  Overlay/             # panel, focus, show/hide
  Grid/                # pages, icons, drag reorder
  Search/              # query + results
  Catalog/             # discovery, identity, launch
  Persistence/         # layout + settings
  Settings/            # shortcut configuration
```

**License:** Prefer an original MIT (or owner-chosen) license. **Do not** copy LaunchNext sources without an explicit owner decision — LaunchNext is **GPL-3.0**.

## 4. Behavior rules (v0.1)

1. Shortcut toggles overlay visibility when registered.
2. Overlay appears on primary display over ordinary desktop and (as far as v0.1 can prove) over another app’s full-screen Space **without** creating an unintended Space — owner must validate on hardware.
3. Click empty background dismisses (implementation default).
4. Escape: clear active search first if any; else dismiss overlay. (Folders do not exist yet.)
5. Typing while browsing starts search; Escape/back clears per above.
6. Launch: request open/activate → dismiss; on failure, keep overlay and show a short error.
7. Reorder: one placement per app; compact gaps on the affected page; do not pull items from later pages; survive restart.
8. New apps append to the end of the layout; do not globally resort after the user has organized.

## 5. Acceptance checks (manual — owner on a real Mac)

Run on Apple Silicon, **macOS 26+** (and note anything untested). Coding agents on Linux **cannot** execute these.

1. App builds and launches from Xcode; menu bar icon appears.
2. Quit from menu bar works; relaunch restores saved layout.
3. Configured shortcut opens and closes the overlay.
4. Overlay covers the primary display; with a second display attached, it does **not** duplicate there.
5. Visible apps match roughly what’s in `/Applications` (helpers/nested bundles may be excluded — document exclusions).
6. Clicking an app launches/activates it and closes the overlay.
7. Typing filters apps; selecting/Return (if implemented) launches; Escape clears then closes.
8. Drag reorder survives quit/relaunch.
9. Unsigned archive from Release instructions installs with expected Gatekeeper warning; app still runs after user override.

Record pass/fail + OS version + hardware. Do not claim macOS 27 or multi-display success without running those cases.

## 7. Build instructions (owner)

1. Install current **Xcode** with macOS 26 SDK on an Apple Silicon Mac.
2. Clone the repo; open `GridBack.xcodeproj` (or the project the agent creates).
3. Select an Apple Silicon run destination; Build (⌘B) then Run (⌘R).
4. Grant any permission prompts the chosen hotkey approach requires; document them in README.
5. For release: Archive or script-package an **unsigned** `.app` (zip or DMG); attach to a GitHub Release with checksum and known limitations (Gatekeeper).

Exact Xcode version / SDK: agent should record what the project file targets; owner records what they actually built with.

## 8. Agent honesty rules (mandatory)

- Cloud / Linux coding agents **cannot** run the macOS UI. They must:
  - Produce a project that **opens and builds cleanly in Xcode** (use whatever static checks are available on the agent host; do not invent green UI tests).
  - State explicitly: **built sources + project structure**, vs **untested on device** (overlay, shortcut, launch, drag, Gatekeeper).
- Do **not** claim pinch, folders, notarization, or “works like Launchpad” beyond the checks above.
- Do **not** claim LaunchNext / LaunchOS parity.
- If blocked (API unavailable, project won’t generate), stop with evidence and the smallest owner decision — do not silently shrink or expand scope.
- Prefer a thin vertical slice that passes the acceptance list over speculative architecture.
